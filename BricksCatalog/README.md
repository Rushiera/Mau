# Mau 积木百科全书 — BricksCatalog

> 版本：v1.0 | 创建：2026-08-04
> 定位：Mau 积木库的全量管理目录——每个积木唯一 ID + 名字 + 路径索引 + 版本状态
> 原则：积木是 Mau 生态的"包"。CH4 所需积木预计 100+，从第一天建立统一登记。

---

## 一、积木 ID 规范

**格式：`BRIK-{类别}-{三位序号}`**

| 段 | 规则 |
|:--|:--|
| `BRIK` | 固定前缀——Mau Brick 命名空间 |
| `{类别}` | 大写类别码：FILE / DATA / TEXT / LOG / LLM / OFFICE / SHELL / APPROVAL / MATH / TEST / FLOW / NET / PLATFORM |
| `{三位序号}` | 001 起顺序分配，**永不重用**（废弃积木保留 ID 标记 Deprecated） |

**示例：** `BRIK-FILE-001` = file.read

**ID 分配规则：**
- 新积木创建时从当前类别最大序号 +1 分配
- 同名积木修改 → ID 不变，版本号 +0.1
- 积木废弃 → 标记 `[Deprecated]`，ID 不释放
- 迁移来源（CH2/CH3）在条目中注明 `来源` 字段

## 三、积木文件头注释规范（代码内）

每个积木 .cs 文件头部必须包含以下注释块：

```csharp
// ═══════════════════════════════════════════════
// 积木: file.read
// ID:   BRIK-FILE-001
// 作用: 读取 UTF-8 文本文件内容
// 引用: Mau.Bricks.Standard → Mau.Contracts / Mau.Runtime
// 原理: 受控文件系统解析路径 → 白名单边界校验 → File.ReadAllText
// 常用: CH4 IO 工具组 / 任意文件读取场景
// ═══════════════════════════════════════════════
```

**字段含义：**

| 字段 | 内容 |
|:--|:--|
| `积木:` | Mau 调用名（`类别.函数`，与 BrickContract.Name 一致） |
| `ID:` | 唯一 ID（BRIK-{类别}-{序号}） |
| `作用:` | 一句话职责——做什么 |
| `引用:` | 依赖链——它引用了哪些库/服务 |
| `原理:` | 核心机制——怎么做（≤一行） |
| `常用:` | 典型使用场景——哪里会用到它 |

## 四、登记流程（新积木三步骤）

1. **写代码** — 在对应 Mau.Bricks.* 工程中实现静态方法 + BrickContract 注册
2. **写文件头** — 按 §三 规范在 .cs 文件头部写注释块（含 ID）
3. **登记** — 在 BricksCatalog/INDEX.md + 对应类别文件（FILE.md 等）追加一行

**删除流程：** 标记 `🗑️ Deprecated` + 保留 ID + 在 INDEX 注明废弃原因。代码可删，登记保留。

---

## 五、版本管理

- 积木版本随 Mau 工程版本走（Mau.sln 整体版本）
- 每个积木的契约变化（端口/语义）→ 记录到 CHANGELOG
- 黄金文件保证生成物确定性——积木实现变化不破坏已生成物（积木静态绑定）
