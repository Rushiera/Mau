- **CH4 现状：** CH4 仓库冻结为语料堆（与 CH2/CH3 同级）——新 CH4 从语料汲取、在 Mau 基座上重新生长，介入模式由使用者重新评估。

### 三位一体

| 位 | 定义 |
|:--|:--|
| **私人方言** | 行为表达格式——语法为 LLM 输出稳定性设计（符号化 + 白名单词法），用确定性验证填补 LLM 的逻辑盲区 |

### 设计灵魂（四条）

1. **私人方言** — 语法只为 CH4 行为表达设计；LLM 可稳定生成是语法第一判据
2. **自检仪** — 分析能力接入门禁段——LLM 写语料，确定性代码验
3. **积木重生判据** — 每个积木过四问：原子性（单时序点/单线程域/叶子）· 可构造性（白名单类型）· 消费面（CH4 自举真实会用——没有"可能"选项）· 归属（机制入口/服务封装）

### 语法 v3 一句话

**FSM 网络是唯一语义，事件是唯一驱动，传感器是唯一感知，TokenId 是唯一内核词汇，外观表是我的私人拼写。**

| 单元 | 命名 | 语义一句话 |
|:--|:--|:--|
| 状态机 | 状态机 | 我在哪——互斥单值，事件沿转移，自环保持 |
| 传感器 | 传感器 | 外界什么样——被动=触发器（事件沿），主动=采样（乱东西进，规范参数出） |
| 导线 | 导线 | 什么响了→敲什么→去哪——可并联（par）、可分叉（\|）、可互联 |
| 槽 | 槽 | 能装多少/占没占——配额·独占·令牌 |

**TokenId 词法内核：** 翻译器只认编号，不认字符——字符是可替换的外观层（C# 接口 `ISymbolAppearance`）。黄金哈希对象 = TokenId 流——换外观不漂移，哨兵只对语义变更报警。

## Git 版本管理规范

### 分支策略

**主干开发（Trunk-Based Development）。**

| 分支 | 用途 | 规则 |
|:--|:--|:--|
| `master` | 唯一真相源 | 始终可编译、可运行门禁 |
| `feature/*` | 新功能/修复 | 从 master 切出，合并回 master |

- 小改动（<200 行）直接在 master 提交
- 中大型改动（≥200 行或跨多项目）走 `feature/` 分支，合并前跑完整门禁
- 不设 `develop`、`release` 等长驻分支

### 提交粒度

**一个提交 = 一个可独立理解的最小变更单元。**

| 规则 | 说明 |
|:--|:--|
| 原子性 | 一个提交只做一件事 |
| 可编译 | 每次提交后 `dotnet build` 零错误 |
| 门禁不倒退 | 不提交已知会破坏门禁的代码 |
| 禁止批量提交 | 不把攒了一周的杂项塞进一个 commit |

**提交信息格式：** `<阶段/范围>: <一句话摘要>` + 可选详细说明。

### 标签规则

版本号 `v<主>.<次>.<修>`：主=架构变更（接口断裂）；次=新功能；修=修复。
