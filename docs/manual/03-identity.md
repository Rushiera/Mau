# 03 · 身份系统

> 一句话：**人格问题找 Worker，能力问题找 Job，运行问题找猫 / 工具。**

## 三个层级

| 术语 | 是什么 | 位置 |
|:--|:--|:--|
| **Worker**（人格） | 主人格单元——语言习惯 + 核心参数 + 行为准则。一次任务唯一 | `L2/Worker/<名>/` |
| **Job**（能力） | 能力单元——只写「怎么解决问题」，被动加载。一次任务 N 个 | `L2/Job/<名>/` |
| **猫（Cat）** | 运行时容器——每猫独立会话 / 端口 / 工具面 / 受控根 / 配置 | 数据区 `sessions/<id>/` |

**判据：** 换人格（语气 / 决策风格）改 Worker；换能力（会不会用 C# 工具）改挂载的 Job；换运行参数（端口 / 工具面 / 配置）改猫。

## Worker 与 Job 的文件结构

**Worker 四件：**

| 件 | 装什么 |
|:--|:--|
| `heart.md` | 角色卡——语言习惯 + 核心参数 + 行为准则 + 职责路由 |
| `skill.md` | 方法论——**怎么想**（认知方法，各自闭环） |
| `exp.md` | 行动语料——**怎么做**（执行流程 / 规范 / 场景速查） |
| `tools.md` | 专属工具——本人格怎么用工具 |

**Job 三件：** `skill.md`（领域认知）· `exp.md`（领域规范）· `tools.md`（领域工具契约）。Job 无 heart、无声明面——它是被动加载的能力块。

## 面——知识按「什么时候读」分层

| 面 | 含义 |
|:--|:--|
| **前文面** | 上工即注入、会话随行的信息（人格件 + 规范固化件） |
| **查询面** | 按需读取的完整文档（手册 / 方法 / 索引） |
| **归档面** | 批处理的历史与判例 |

**自足律：** 前文面内不得存在指向未注入文件的「必须项」引用——保证新会话零工具调用即可回答「我是谁 / 能干什么 / 边界在哪」。

## 对使用者意味着什么

- 每只猫 = 一个 Worker 的实例 + 若干 Job；面板里逐猫配置人格（persona）与工具面（toolNames）。
- 想让猫「会某件事」→ 给它挂对应 Job；想让它「是另一种性格」→ 换 / 调 Worker。
- 身份与工具面都是**可裁剪的**——猫的能力边界由你定义。
